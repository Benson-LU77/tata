# Tata 維護迴圈

> Tata 不是蓋完就好的房子,是要澆水的城市。這份文件寫清楚:平常怎麼養、出事怎麼修、多久看一次什麼。
> 分四個迴圈:**日常開發**、**Bug 處理**、**發版**、**定期健檢**。

## 迴圈一:日常開發(每次改碼)

```mermaid
flowchart LR
    A[改程式] --> B["npm test<br/>(74 條)"] --> C["npx tsc --noEmit"] --> D[瀏覽器/模擬器實測] --> E[commit + push] --> F["自動:post-commit hook<br/>寫進 Obsidian 開發日記"] --> G[更新長期記憶]
```

鐵則(每一條都是踩過雷才立的):

| 規則 | 為什麼 |
|---|---|
| 改完必跑 `tsc` | vite build **不做型別檢查**,曾漏掉 seed 欄位讓鄰居三天都是預設臉 |
| 互動驗證用真實點擊(computer 工具),不用 JS `.click()` | `.click()` 繞過命中測試,曾漏掉「按鈕點不到」 |
| 改台詞必同步改 `bonds-answers.ts` 鍵名 | answers.test 強制 100% 覆蓋,鍵=開場句英文全文 |
| 新增 sprite 必過 `zz-sprite-guard.test` | 一個非法字元=啟動全黑畫面 |
| 手機 CSS 覆寫一律放 globals.css 檔尾 | 同權重後者贏,已踩 5 次 |
| python 批次替換必加 assert | 無聲失敗兩次讓功能「半上線」 |

## 迴圈二:Bug 處理(使用者回報)

```mermaid
flowchart LR
    A["回報<br/>(截圖/設定面板診斷條)"] --> B[重現] --> C[找根因<br/>不是找症狀] --> D[寫測試釘死] --> E[修] --> F[部署] --> G[記進記憶/問題總表]
```

- **診斷通道**:app 內建環形日誌(`debuglog.ts`),設定面板底部有診斷條——使用者截設定面板圖=自帶錯誤現場。
- **測試先釘再修**:8/21 資料遺失事故後的慣例;測試要能在「舊的壞程式」上失敗才算釘住。
- 根因要能解釋**全部**症狀;解釋不了的部分就是還沒找到根因(人口潮汐案:對話照跑、人卻消失)。

## 迴圈三:發版

### 網頁(tata.page)——隨改隨發
1. 迴圈一全綠 → `npm run deploy`(gh-pages,CNAME 檔會自動帶上,少了它自訂網域會掉)。
2. PWA 是「更新提示制」:使用者看到提示按更新才換版,寫作中不打擾。
3. 發完自己重整實測一次(SW 快取,必要時重整兩次)。

### iOS(App Store)
1. `npm run ios:sync`(會自動補回 VaultPlugin 註冊——`cap sync` 會把它洗掉)。
2. Release 建置跑模擬器過一遍主流程(寫一頁→收書→相遇→補給站)。
3. Xcode:**Build 號 +1** → Any iOS Device → Archive → Upload → 送審。
4. 文案照 `appstore-copy.md`,隱私=不收集資料。

## 迴圈四:定期健檢

| 頻率 | 做什麼 |
|---|---|
| 每次大功能前 | 交叉檢核(architect 深讀 + codex 第二意見),重大決策才觸發 |
| 每月 | `npm audit` + 依賴升級評估;CI 是否仍全綠;`npm outdated` 看主要套件 |
| 每季 | 全站易用性走查(照 2026-08-16 清單的做法:逐畫面、桌機+手機);對比度掃一輪 |
| 域名/憑證 | tata.page 自動續約已開;若憑證卡住:拆掉 cname 再重綁即刻觸發 |
| 資料安全 | 抽查影子備份是否在寫(IndexedDB "shadows",每檔 3 份);跑 fs-bridge 守衛測試 |
